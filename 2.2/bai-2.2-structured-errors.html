Bài tập 2.2 — Structured Error Responses cho cả 4 loại lỗi

Domain 2 · Tool Design & MCP Integration · Mục 2.2 Structured Error Responses
Người thực hiện: TruongNQ · Ngày nộp: 13/10/2026

1. Mục tiêu

Xây một MCP server có tool tra khách và hoàn tiền, trả lỗi có cấu trúc cho đủ 4 loại (transient, validation, business, permission), tách bạch kết quả rỗng hợp lệ với lỗi truy cập, rồi viết vòng hồi phục rẽ nhánh theo metadata. Cùng bộ kịch bản được chạy lại với lỗi kiểu cũ (chỉ chữ "Error") để thấy agent mất phương hướng ra sao.

Bài này chạy thật được không cần model. Vòng hồi phục ở recovery_agent.ts là logic tất định bằng code, server là MCP stdio thật, nên log ở mục 7 là đầu ra thật. Phần để Claude tự quyết dựa vào metadata (run_llm.sh) là tuỳ chọn và chưa chạy (mục 8).

3. Năm bước ↔ cách hiện thực

#Yêu cầuHiện thực
1MCP tool tra khách trên DB giả, có tham số kích hoạt lỗi theo yêu cầusupport_mcp_server.ts (stdio, JSON-RPC 2.0, TypeScript; lớp JSON-RPC viết tay trong file để thấy rõ chỗ tách lỗi giao thức và lỗi thực thi). get_customer(customer_id, simulate?) với simulate = none | timeout | flaky:N | permission; thêm process_refund(customer_id, amount) để có lỗi business. DB giả 3 khách, CUS-0777 là hồ sơ tài chính bị hạn chế
2Bốn lỗi: timeout, sai định dạng, hoàn tiền vượt hạn mức, bị từ chối quyềntransientTimeout, validationBadId, business trong processRefund (> 500 USD), permissionDenied. Tất cả isError: true, chỉ transient có isRetryable: true
3Metadata đúng 3 field: category, retry, description gợi ý bước tiếptoolError đặt {errorCategory, isRetryable, description} vào structuredContent và lặp lại dạng JSON trong content (cho client chỉ đọc text). Mỗi description nói rõ vì sao và làm gì tiếp
4Rỗng hợp lệ khác hẳn lỗi truy cậpvalidEmpty: isError: false, resultCount: 0, message "truy vấn đã chạy, không cần gọi lại". Lỗi truy cập: isError: true, transient, retryable. Hai bên không chung key nào (test kiểm tra)
5Vòng agent rẽ nhánh: transient ≤ 3 lần có backoff, validation sửa input, business escalate, permission xin quyềnrecovery_agent.ts → handleStructured. Backoff 0.2 → 0.4 → 0.8s. Validation chuẩn hoá "cus 12" → CUS-0012. Business tạo handoff (mã khách, số tiền, lý do). Không bao giờ gọi lại business/permission. Có thêm kịch bản lan truyền lỗi tra 3 khách

Quy ước đếm: 1 lần gọi đầu + tối đa 3 lần retry = tối đa 4 lần gọi cho lỗi transient. Lần gọi lại sau khi sửa input validation là lần gọi mới, không tính là retry.

Lưu ý: errorCategory, isRetryable, description là quy ước của ứng dụng, không có trong MCP spec. CallToolResult của MCP chỉ định nghĩa content, structuredContent, isError. Đề thi dùng 4 loại và cờ retry này, nhưng đừng nói chúng là "trường chuẩn của MCP".
Vì sao customer_id không có pattern trong inputSchema? Nếu schema chặn định dạng, client/SDK có thể từ chối ngay ở lớp giao thức: tool không chạy, agent không nhận được lỗi validation có hướng dẫn sửa. Bài này kiểm định dạng trong code để trả lỗi validation có cấu trúc. (Ngược lại, thiếu hẳn tham số bắt buộc thì server trả JSON-RPC error, minh hoạ lớp 1.)

Nếu hai trường hợp trông giống nhau (bản bad trả "Error" cho cả hai), agent sẽ retry 3 lần một khách không tồn tại rồi escalate vô ích: đúng tình huống trong câu luyện tập của bài.

#!/usr/bin/env -S node --experimental-strip-types --no-warnings
// Bài 2.2 – MCP server "support" (stdio, JSON-RPC 2.0, TypeScript, không cần thư viện ngoài).
//
// Hai tool:
//   get_customer(customer_id, simulate?)  – tra hồ sơ khách trong DB giả
//   process_refund(customer_id, amount)   – hoàn tiền, hạn mức tự động 500 USD
//
// Hai lớp lỗi:
//   1. Protocol error (JSON-RPC `error`): tool không tồn tại, thiếu tham số bắt buộc. Không có tool nào chạy,
//      model không nhận được tool result. Sửa ở schema/client, không phải ở vòng hồi phục của agent.
//   2. Tool execution error (`result.isError: true`): tool đã chạy nhưng thất bại. Metadata nằm trong
//      structuredContent: { errorCategory, isRetryable, description }. Đây là QUY ƯỚC CỦA ỨNG DỤNG,
//      MCP spec chỉ định nghĩa content / structuredContent / isError.
//
// Lớp JSON-RPC viết tay ngay trong file (không dùng lib/mcp_server.ts) để thấy rõ chỗ tách hai lớp lỗi:
// kiểm tool tồn tại + tham số bắt buộc → `error`; còn lại → `result`.
//
// Lưu ý: customer_id KHÔNG khai báo `pattern` trong inputSchema. Nếu schema chặn định dạng thì client/SDK
// có thể từ chối ngay ở lớp giao thức và agent không bao giờ thấy lỗi validation có hướng dẫn sửa.
// Định dạng được kiểm trong code để trả lỗi validation có cấu trúc.
//
// Tham số simulate (chỉ để kích hoạt lỗi theo yêu cầu):
//   none (mặc định) | timeout (luôn timeout) | flaky:N (N lần đầu timeout, sau đó chạy bình thường)
//   | permission (giả lập service account bị thu quyền)
//
// Biến môi trường:
//   ERROR_STYLE=structured (mặc định) | bad   – bad: mọi lỗi chỉ là chuỗi "Error", kết quả rỗng cũng là "Error"
//   SUPPORT_LOG=<file>                         – mỗi tools/call ghi 1 dòng JSON

import { createInterface } from "node:readline";
import type { ToolDef, ToolResult } from "../lib/mcp_server.ts";

const ERROR_STYLE = process.env.ERROR_STYLE ?? "structured";
const LOG_FILE = process.env.SUPPORT_LOG;
const REFUND_LIMIT = 500;

interface Customer {
  customer_id: string; name: string; tier: string; balance_usd: number; orders: string[]; restricted: boolean;
}

// Dữ liệu GIẢ.
const CUSTOMERS: Record<string, Customer> = {
  "CUS-0012": { customer_id: "CUS-0012", name: "Nguyễn Thị Lan", tier: "Vàng", balance_usd: 120.0,
                orders: ["#12345", "#31007"], restricted: false },
  "CUS-0042": { customer_id: "CUS-0042", name: "Trần Văn Minh", tier: "Bạc", balance_usd: 0.0,
                orders: ["#20871"], restricted: false },
  // Hồ sơ thuộc nhóm tài chính bị hạn chế: service account của agent không có quyền đọc.
  "CUS-0777": { customer_id: "CUS-0777", name: "Công ty TNHH Hoà Phát Đạt", tier: "Doanh nghiệp",
                balance_usd: 15_400.0, orders: ["#45210"], restricted: true },
};

const TOOLS: (ToolDef & { inputSchema: { required: string[] } })[] = [
  { name: "get_customer",
    description: [
      "Tra hồ sơ khách hàng theo mã khách dạng CUS-NNNN (vd CUS-0012): tên, hạng, số dư, danh sách mã đơn.",

                     customer_id: { type: "string", description: "Mã khách dạng CUS-NNNN, vd CUS-0012" },

                   },
                   required: ["customer_id"] } },

    description: [
      `Hoàn tiền cho khách (USD). Tự động duyệt tối đa ${REFUND_LIMIT} USD; vượt hạn mức trả lỗi business, không gọi lại mà chuyển quản lý duyệt.`,

                   properties: {
                     customer_id: { type: "string", description: "Mã khách dạng CUS-NNNN" },

                   },
                   required: ["customer_id", "amount"] } },

const ID_FORMAT = /^CUS-\d{4}$/;
const flakyCounts = new Map<string, number>(); // (customer_id, simulate) → số lần đã gọi, để flaky:N hết lỗi sau N lần

type Args = Record<string, unknown>;

function logCall(name: string, args: Args): void {
  if (LOG_FILE) appendFileSync(LOG_FILE, JSON.stringify({ at: new Date().toISOString(), tool: name, arguments: args }) + "\n");
}

// ---- Hai kiểu trả lỗi -------------------------------------------------------------------------

type Category = "transient" | "validation" | "business" | "permission";

function toolError(category: Category, retryable: boolean, description: string): ToolResult {
  if (ERROR_STYLE === "bad") return { content: [{ type: "text", text: "Error" }], isError: true };

  const meta = { errorCategory: category, isRetryable: retryable, description };
  return { content: [{ type: "text", text: JSON.stringify(meta) }], structuredContent: meta, isError: true };
}

function toolOk(data: Record<string, unknown>): ToolResult {
  return { content: [{ type: "text", text: JSON.stringify(data) }], structuredContent: data, isError: false };
}

function validEmpty(customerId: string): ToolResult {
  // Bản bad: "không có kết quả" trông y hệt lỗi, agent không phân biệt được.
  if (ERROR_STYLE === "bad") return { content: [{ type: "text", text: "Error" }], isError: true };

  return toolOk({ results: [], resultCount: 0,
    message: `Truy vấn đã chạy thành công, không có khách nào có mã ${customerId}. Không cần gọi lại.` });
}

// ---- Các lỗi theo 4 loại ----------------------------------------------------------------------

const transientTimeout = () =>
  toolError("transient", true,
    "Kết nối DB khách hàng bị timeout sau 5s, truy vấn CHƯA chạy (dữ liệu có thể vẫn tồn tại). " +
    "Yêu cầu hợp lệ: gọi lại nguyên văn sau vài trăm ms.");

const validationBadId = (raw: string) =>
  toolError("validation", false,
    `customer_id '${raw}' sai định dạng. Định dạng đúng: CUS + gạch ngang + 4 chữ số, vd CUS-0012. ` +
    "Gọi lại y nguyên sẽ lỗi tiếp: hãy sửa input rồi gọi lại, hoặc hỏi lại khách mã đúng.");

const permissionDenied = (customerId: string) =>
  toolError("permission", false,
    `Service account support-bot không có quyền đọc hồ sơ tài chính của ${customerId}. ` +
    "Gọi lại với cùng tài khoản sẽ vẫn bị từ chối: chuyển cho nhân viên cấp cao có quyền finance-read.");

function simulatedFailure(customerId: string, simulate: unknown): ToolResult | null {
  if (simulate == null || simulate === "" || simulate === "none") return null;
  if (simulate === "timeout") return transientTimeout();
  if (simulate === "permission") return permissionDenied(customerId);
  const m = /^flaky:(\d+)$/.exec(String(simulate));
  if (m) {
    const key = `${customerId}|${simulate}`;
    const n = (flakyCounts.get(key) ?? 0) + 1;
    flakyCounts.set(key, n);
    return n <= Number(m[1]) ? transientTimeout() : null;
  }
  return toolError("validation", false,
    `simulate '${simulate}' không hợp lệ. Giá trị cho phép: none, timeout, flaky:N, permission.`);
}

function getCustomer(args: Args): ToolResult {
  const id = String(args.customer_id ?? "");
  if (!ID_FORMAT.test(id)) return validationBadId(id);

  const failure = simulatedFailure(id, args.simulate);
  if (failure) return failure;

  const customer = CUSTOMERS[id];
  if (!customer) return validEmpty(id);
  if (customer.restricted) return permissionDenied(id);

  const { restricted: _, ...visible } = customer;
  return toolOk({ results: [visible], resultCount: 1 });
}

function processRefund(args: Args): ToolResult {
  const id = String(args.customer_id ?? "");
  const amount = args.amount;
  if (!ID_FORMAT.test(id)) return validationBadId(id);
  if (typeof amount !== "number" || !(amount > 0)) {
    return toolError("validation", false, `amount '${amount}' không hợp lệ: phải là số dương (USD), vd 49.5.`);
  }

  const customer = CUSTOMERS[id];
  if (!customer) {
    return toolError("validation", false,
      `Không có khách ${id} nên không thể hoàn tiền. Kiểm tra lại mã khách bằng get_customer trước.`);
  }
  if (customer.restricted) return permissionDenied(id);

  if (amount > REFUND_LIMIT) {
    return toolError("business", false,
      `Khoản hoàn ${amount.toFixed(2)} USD vượt hạn mức tự động ${REFUND_LIMIT} USD, cần quản lý duyệt. ` +
      "KHÔNG gọi lại: tạo yêu cầu duyệt cho quản lý kèm mã khách, số tiền, lý do; " +
      "báo khách rằng yêu cầu đang chờ duyệt trong 1 ngày làm việc.");
  }

  return toolOk({ refund_id: `RF-${id.slice(-4)}-${Math.trunc(amount * 100)}`, customer_id: id, amount_usd: amount,
                  status: "approved" });
}

const HANDLERS: Record<string, (args: Args) => ToolResult> = { get_customer: getCustomer, process_refund: processRefund };

// ---- JSON-RPC ---------------------------------------------------------------------------------

type Id = number | string | null | undefined;
const write = (msg: unknown) => process.stdout.write(JSON.stringify(msg) + "\n");
const respond = (id: Id, result: unknown) => write({ jsonrpc: "2.0", id, result });
const respondError = (id: Id, code: number, message: string) =>
  write({ jsonrpc: "2.0", id: id ?? null, error: { code, message } });

createInterface({ input: process.stdin }).on("line", (line) => {
  if (!line.trim()) return;
  let msg: { id?: Id; method?: string; params?: Record<string, any> };
  try {
    msg = JSON.parse(line);
  } catch {
    respondError(null, -32700, "Parse error");
    return;
  }
  const { id, method, params = {} } = msg;
  switch (method) {
    case "initialize":
      respond(id, { protocolVersion: params.protocolVersion ?? "2025-06-18",
                    capabilities: { tools: {} }, serverInfo: { name: "support", version: "1.0.0" } });
      return;
    case "notifications/initialized":
    case "notifications/cancelled":
      return;
    case "ping":
      respond(id, {});
      return;
    case "tools/list":
      respond(id, { tools: TOOLS });
      return;
    case "tools/call": {
      const name = String(params.name ?? "");
      const args: Args = params.arguments ?? {};
      const tool = TOOLS.find((t) => t.name === name);
      // Lớp 1 – protocol error: tool không tồn tại hoặc thiếu tham số bắt buộc → tool không chạy.
      if (!tool) {
        respondError(id, -32602, `Unknown tool: ${name}`);
        return;
      }
      const missing = tool.inputSchema.required.filter((k) => !(k in args));
      if (missing.length) {
        respondError(id, -32602, `Invalid params for ${name}: missing ${missing.join(", ")}`);
        return;
      }
      // Lớp 2 – tool chạy; lỗi (nếu có) nằm trong result.isError.
      logCall(name, args);
      respond(id, HANDLERS[name](args));
      return;
    }
    default:
      if (id != null) respondError(id, -32601, `Method not found: ${method}`);
  }
});

// Bài 2.2 – Vòng hồi phục đọc metadata lỗi và rẽ nhánh.
//
// Đây là logic TẤT ĐỊNH bằng code: không gọi model, nên chạy thật được ngay. Nó đóng vai phần
// "agent" quyết định sau mỗi tool result. (Phần để LLM tự quyết dựa vào cùng metadata: xem run_llm.sh.)
//
//   isRetryable = true  (transient)  → gọi lại nguyên văn, tối đa 3 lần, backoff 0.2s → 0.4s → 0.8s
//   validation                       → sửa input (chuẩn hoá mã khách) rồi gọi lại 1 lần; không sửa được → hỏi lại khách
//   business                         → KHÔNG gọi lại, escalate kèm handoff (mã khách, số tiền, lý do)

export const SERVER = join(import.meta.dirname, "support_mcp_server.ts");
export const MAX_RETRIES = 3;
const BASE_DELAY = 0.2;
const backoffScale = () => Number(process.env.BACKOFF_SCALE ?? "1");

type Style = "structured" | "bad";
type Args = Record<string, unknown>;
export type Outcome = "success" | "not_found" | "gave_up" | "ask_user" | "escalated" | "need_credentials" | "protocol_error";

export interface Handoff { customer_id: unknown; amount_usd: unknown; reason: string; recommended_action: string }
export interface RunResult {
  outcome: Outcome;
  delays: number[];
  data?: Record<string, unknown>;
  attempted?: number;
  handoff?: Handoff;
}

/** Client MCP có đếm số lần tools/call. Mỗi kịch bản một server mới để bộ đếm flaky tách bạch. */
class CountingClient {
  calls = 0;
  private client: McpClient;

  constructor(style: Style) {
    const env: Record<string, string> = { ERROR_STYLE: style };
    if (process.env.SUPPORT_LOG) env.SUPPORT_LOG = process.env.SUPPORT_LOG;
    this.client = McpClient.forTsServer(SERVER, env);
  }

  init() { return this.client.initialize(); }

  callTool(name: string, args: Args): Promise<RpcResponse> {
    this.calls++;
    return this.client.callTool(name, args);
  }

  close() { this.client.close(); }
}

/** Thử sửa mã khách sai định dạng: "cus 12", "cus-0012", "CUS12" → "CUS-0012". Không đoán được thì null. */
export function fixCustomerId(raw: unknown): string | null {
  const m = /^cus[\s\-_]*(\d{1,4})$/i.exec(String(raw ?? "").trim());
  return m ? `CUS-${String(Number(m[1])).padStart(4, "0")}` : null;
}

function metadataOf(result: any): any {
  if (result.structuredContent) return result.structuredContent;
  try {
    return JSON.parse(String(result.content?.[0]?.text ?? ""));
  } catch {
    return null;
  }
}

async function handleStructured(client: CountingClient, tool: string, args: Args, log: string[]): Promise<RunResult> {
  let retries = 0;
  let fixed = false;
  const delays: number[] = [];
  const scale = backoffScale();
  for (;;) {
    const resp = await client.callTool(tool, args);
    if (resp.error) {
      log.push(`  ✗ lớp giao thức ${resp.error.code}: ${resp.error.message} → tool không chạy, báo dev sửa schema/client`);
      return { outcome: "protocol_error", delays };
    }

    const result = resp.result;
    const meta = metadataOf(result);
    if (!result.isError) {
      if (meta.resultCount === 0) {
        log.push("  ○ rỗng hợp lệ (isError=false, resultCount=0) → trả lời khách: không tìm thấy, KHÔNG gọi lại");
        return { outcome: "not_found", delays };
      }
      log.push(`  ✓ thành công: ${JSON.stringify(meta).slice(0, 110)}`);
      return { outcome: "success", data: meta, delays };
    }

    const category = meta.errorCategory;
    log.push(`  ! ${category} (isRetryable=${meta.isRetryable}): ${String(meta.description).slice(0, 90)}…`);
    if (meta.isRetryable) {
      if (retries >= MAX_RETRIES) {
        log.push(`  ✗ hết ${MAX_RETRIES} lần retry → báo lên: đã thử ${client.calls} lần, lỗi transient, chưa có dữ liệu`);
        return { outcome: "gave_up", attempted: retries + 1, delays };
      }
      const delay = BASE_DELAY * 2 ** retries * scale;
      retries++;
      delays.push(delay);
      log.push(`    ↻ retry ${retries}/${MAX_RETRIES} sau ${(delay / scale).toFixed(2)}s`);
      await sleep(delay * 1000);
      continue;
    }

    switch (category) {
      case "validation": {
        const candidate = fixCustomerId(args.customer_id);
        if (!fixed && candidate && candidate !== args.customer_id) {
          log.push(`    ✎ sửa input customer_id '${args.customer_id}' → '${candidate}' rồi gọi lại (lần gọi mới, không phải retry)`);
          args = { ...args, customer_id: candidate };
          fixed = true;
          continue;
        }
        log.push("  ? không tự sửa được → hỏi lại khách mã đúng (dạng CUS-NNNN)");
        return { outcome: "ask_user", delays };
      }
      case "business": {
        const handoff: Handoff = { customer_id: args.customer_id, amount_usd: args.amount, reason: meta.description,
                                   recommended_action: "Quản lý duyệt hoàn tiền vượt hạn mức" };
        log.push(`  ⇧ escalate cho quản lý, KHÔNG retry. Handoff: ${JSON.stringify(handoff).slice(0, 120)}…`);
        return { outcome: "escalated", handoff, delays };
      }
      case "permission":
        log.push("  🔑 xin quyền finance-read / chuyển nhân viên cấp cao, KHÔNG retry với cùng tài khoản");
        return { outcome: "need_credentials", delays };
      default:
        log.push(`  ✗ errorCategory lạ '${category}' → escalate`);
        return { outcome: "escalated", delays };
    }
  }
}

// ---- Agent "ngây thơ" với lỗi kiểu cũ: chỉ biết isError + chữ "Error" ---------------------------
// Không có category hay isRetryable, cách duy nhất là đoán: thử lại 3 lần rồi chuyển người.

async function handleNaive(client: CountingClient, tool: string, args: Args, log: string[]): Promise<RunResult> {
  let retries = 0;
  const delays: number[] = [];
  const scale = backoffScale();
  for (;;) {
    const resp = await client.callTool(tool, args);
    if (resp.error) {
      log.push(`  ✗ lớp giao thức: ${resp.error.message}`);
      return { outcome: "protocol_error", delays };
    }
    const result = resp.result;
    if (!result.isError) {
      log.push("  ✓ thành công");
      return { outcome: "success", delays };
    }
    log.push(`  ! "${result.content?.[0]?.text}" (không biết loại lỗi, không biết có nên thử lại)`);
    if (retries >= MAX_RETRIES) {
      log.push(`  ⇧ thử ${client.calls} lần vẫn lỗi → chuyển người xử lý`);
      return { outcome: "escalated", delays };
    }
    const delay = BASE_DELAY * 2 ** retries * scale;
    retries++;
    delays.push(delay);
    log.push(`    ↻ đoán là lỗi tạm thời, thử lại ${retries}/${MAX_RETRIES}`);
    await sleep(delay * 1000);
  }
}

export async function runScenario(style: Style, sc: Scenario): Promise<RunResult & { calls: number; log: string[] }> {
  const client = new CountingClient(style);
  try {
    await client.init();
    const log: string[] = [];
    const r = await handle(style)(client, sc.tool, { ...sc.args }, log);
    return { ...r, calls: client.calls, log };
  } finally {
    client.close();
  }
}

export async function runBatch(style: Style) {
  const ids: [string, string | null][] = [["CUS-0012", null], ["CUS-0042", "timeout"], ["CUS-9999", null]];
  const client = new CountingClient(style);
  try {
    await client.init();
    const found: string[] = [];
    const empty: string[] = [];
    const failed: { customer_id: string; outcome: Outcome }[] = [];
    const log: string[] = [];
    for (const [id, sim] of ids) {
      const args: Args = { customer_id: id };
      if (sim) args.simulate = sim;
      const r = await handle(style)(client, "get_customer", args, log);
      if (r.outcome === "success") found.push(id);
      else if (r.outcome === "not_found") empty.push(id);
      else failed.push({ customer_id: id, outcome: r.outcome });
    }
    const report = { searched: ids.length, found, not_found: empty, failed, total_calls: client.calls };
    return { report, log };
  } finally {
    client.close();
  }
}

# recovery_agent.ts đã chứng minh logic rẽ nhánh bằng code; script này xem MODEL có đọc metadata
# và tự hành xử đúng không (không retry rỗng/business, sửa mã khách, xin quyền…).
#
# Dùng:  ./run_llm.sh structured | bad | all    chạy 5 prompt × kiểu lỗi (MỖI prompt một lệnh `claude -p`)
#        ./run_llm.sh report                     in bảng: số lần gọi tool, tool đã gọi, câu trả lời cuối
#        ./run_llm.sh clean
#
# Chi phí ước tính (haiku): 10 lệnh, mỗi lệnh 1–5 lượt ≈ 0,15–0,4 USD; mỗi lệnh chặn trần --max-budget-usd.
set -euo pipefail

ROOT="$(cd "$(dirname "${BASH_SOURCE[0]}")" && pwd)"
RESULTS="${RESULTS_DIR:-$ROOT/results_llm}"   # test đặt RESULTS_DIR riêng
NODE="${NODE_BIN:-node}"
MODEL="${MODEL:-haiku}"
BUDGET="${BUDGET:-0.2}"
CLAUDE_BIN="${CLAUDE_BIN:-claude}"

PROMPTS=(
  "Tra giúp tôi hồ sơ khách CUS-9999."
  "Khách CUS-0012 nhận hàng lỗi, hoàn cho họ 750 USD."
  "Xem số dư của khách CUS-0777."
  "Tra khách cus 12 giúp tôi."
  "Tra khách CUS-0042. Đây là môi trường test: truyền simulate=flaky:2."
)
SYSTEM_PROMPT="Bạn là agent CSKH. Dùng tool để trả lời. Khi tool lỗi, hãy quyết định bước tiếp theo hợp lý rồi trả lời ngắn gọn bằng tiếng Việt."

run_style() {
  local style="$1" i mcp
  local dir="$RESULTS/$style"
  mkdir -p "$dir"
  echo "== ERROR_STYLE=$style, model=$MODEL"
  for i in "${!PROMPTS[@]}"; do
    mcp="$dir/p$i.mcp.json"
    rm -f "$dir/p$i.log"
    "$NODE" -e 'const [srv, style, log, node] = process.argv.slice(1);
      console.log(JSON.stringify({ mcpServers: { support: { type: "stdio", command: node,
        args: ["--experimental-strip-types", "--no-warnings", srv], env: { ERROR_STYLE: style, SUPPORT_LOG: log } } } }, null, 2))' \
      "$ROOT/support_mcp_server.ts" "$style" "$dir/p$i.log" "$(command -v "$NODE")" > "$mcp"
    echo "  p$i: ${PROMPTS[$i]}"
    (cd "$RESULTS" && "$CLAUDE_BIN" -p "${PROMPTS[$i]}" \
      --model "$MODEL" \
      --system-prompt "$SYSTEM_PROMPT" \
      --mcp-config "$mcp" --strict-mcp-config \
      --tools "" \
      --allowedTools "mcp__support__get_customer" "mcp__support__process_refund" \
      --permission-mode dontAsk \
      --max-budget-usd "$BUDGET" \
      --no-session-persistence \
      --output-format stream-json --verbose \
      > "$dir/p$i.jsonl" 2> "$dir/p$i.err") || echo "    (lệnh trả mã lỗi, xem $dir/p$i.err)"
  done
}

report() {
  "$NODE" --experimental-strip-types --no-warnings "$ROOT/report_llm.ts" "$RESULTS" "${PROMPTS[@]}"
}

case "${1:-}" in
  structured|bad) run_style "$1" ;;
  all)    run_style structured; run_style bad; report ;;
  report) report ;;
  clean)  rm -rf "$RESULTS" ;;
  *) echo "Dùng: $0 structured|bad|all|report|clean"; exit 1 ;;
esac
report_llm.ts
// Bài 2.2 – in bảng cho run_llm.sh: mỗi prompt gọi tool nào, bao nhiêu lần, câu trả lời cuối.
// Dùng: node --experimental-strip-types report_llm.ts <results_llm> <prompt0> <prompt1> …
import { existsSync } from "node:fs";
import { join } from "node:path";
import { readStream, resultEvent, toolUses } from "../lib/cli_stream.ts";

const [dirArg, ...prompts] = process.argv.slice(2);
for (const style of ["structured", "bad"]) {
  const dir = join(dirArg, style);
  if (!existsSync(dir)) continue;
  console.log(`== ${style}`);
  prompts.forEach((p, i) => {
    const f = join(dir, `p${i}.jsonl`);
    if (!existsSync(f)) return;
    const ev = readStream(f);
    const calls = toolUses(ev).map((t) => `${t.name.replace("mcp__support__", "")}(${JSON.stringify(t.input)})`);
    const final = resultEvent(ev);
    console.log(`  p${i}: ${p}`);
    console.log(`     ${calls.length} lần gọi: ${calls.join(" → ")}`);
    console.log(`     trả lời: ${String(final?.result ?? "").replace(/\s+/g, " ").slice(0, 160)}`);
  });
}

10. Tiêu chí hoàn thành

  • MCP server chạy được, kích hoạt được từng loại lỗi (simulate, dữ liệu, số tiền)
  • Mỗi lỗi có isError: true, đúng category, chỉ transient có isRetryable: true, description nêu vấn đề và bước tiếp
  • Metadata đúng 3 field; business đánh dấu không retry và chỉ sang escalate
  • Rỗng hợp lệ (isError: false, resultCount: 0) khác hẳn lỗi truy cập
  • Vòng agent rẽ nhánh đúng, transient ≤ 3 retry với delay tăng dần, không bao giờ retry business/permission

11. Bài học rút ra

  • Hai lớp lỗi: protocol error (tool không chạy, sửa schema/client) khác tool execution error (tool chạy rồi thất bại, model tự quyết dựa vào isError + metadata).
  • Đọc isRetryable trước, errorCategory sau. false nghĩa là "đừng gửi lại y nguyên", không phải "bỏ cuộc".
  • Rỗng hợp lệ không phải lỗi. Đây là điểm quan trọng nhất của domain: lẫn lộn hai thứ gây retry lãng phí và escalate sai.
  • Lan truyền có chọn lọc: subagent tự retry lỗi tạm thời; chỉ báo lên thứ không tự xử lý được, kèm kết quả một phần và những gì đã thử.

Bẫy đề

  1. Retry kết quả rỗng hợp lệ (tăng retry limit, nới ngưỡng escalate đều sai).
  2. Thông báo lỗi chung chung, không có category / retry / description.
  3. Coi lỗi business là retryable.
  4. Đánh dấu validation isRetryable: true chỉ vì agent sửa được (gửi lại y nguyên vẫn lỗi).
  5. Hiểu isRetryable: false là bỏ task.
  6. Subagent nuốt lỗi, trả rỗng như thành công: coordinator không phân biệt "không có" với "không tìm được".

Ngoài ra: cấm retry hoàn toàn trong system prompt (phương án B của câu luyện tập) là sửa quá tay, chặn cả retry chính đáng cho lỗi tạm thời.
