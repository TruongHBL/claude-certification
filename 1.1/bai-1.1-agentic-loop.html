1. Mục tiêu

Tự viết một vòng lặp agent bằng Messages API (không dùng Agent SDK) với 2 tool: web_search (giả lập) và calculator. Vòng lặp chỉ dựa vào stop_reason để quyết định chạy tiếp hay dừng. Câu hỏi thử cần tìm số liệu trước rồi mới tính, nên bắt buộc phải có nhiều vòng gọi tool liên tiếp.

bai_1_1_agentic_loop.ts

// Bài 1.1 – Build Exercise: Multi-Tool Agent Loop.
//
// Vòng lặp agent tự viết bằng Messages API với 2 tool (calculator, web_search giả lập).
// Điều khiển vòng lặp CHỈ bằng stop_reason: "tool_use" → chạy tool, nối kết quả, lặp tiếp;
// "end_turn" → trả kết quả. MAX_ITERATIONS chỉ là lưới an toàn.
//
// Chạy:  export ANTHROPIC_API_KEY=...
//        node --experimental-strip-types bai_1_1_agentic_loop.ts ["câu hỏi"]
// Không có API key: dùng bản CLI (./run_cli.sh).

import { pathToFileURL } from "node:url";
import { httpTransport, type Message, type Tool, type Transport, type UserBlock } from "../lib/anthropic.ts";
import { TOOL_SPECS, runTool } from "./tools.ts";

const MODEL = "claude-sonnet-5-5";
export const MAX_ITERATIONS = 20; // lưới an toàn, KHÔNG phải điều kiện dừng chính

export const TOOLS: Tool[] = TOOL_SPECS.map((t) => ({ name: t.name, description: t.description, input_schema: t.schema }));

// ---------- Agentic loop ----------
export async function agent(question: string, send: Transport, log = console.log): Promise<string | null> {
  const messages: Message[] = [{ role: "user", content: question }];
  for (let i = 0; i < MAX_ITERATIONS; i++) {
    const r = await send({ model: MODEL, max_tokens: 2000, tools: TOOLS, messages });
    messages.push({ role: "assistant", content: r.content }); // luôn nối lượt của Claude vào history

    switch (r.stop_reason) {
      case "end_turn":
        return r.content.flatMap((b) => (b.type === "text" ? [b.text] : [])).join("");
      case "tool_use": {
        const results: UserBlock[] = r.content.flatMap((b) => {
          if (b.type !== "tool_use") return [];
          const [out, err] = runTool(b.name, b.input);
          log(`[iter ${i}] ${b.name}(${JSON.stringify(b.input)}) → ${out}`);
          return [{ type: "tool_result", tool_use_id: b.id, content: out, is_error: err }];
        });
        messages.push({ role: "user", content: results }); // mọi kết quả trong MỘT message user
        break;
      }
      default: // max_tokens, refusal, pause_turn... → không coi là xong, báo ra để xử lý
        throw new Error(`Dừng bất thường: stop_reason=${r.stop_reason}`);
    }
  }
  console.warn(`CẢNH BÁO: chạm MAX_ITERATIONS=${MAX_ITERATIONS} — vòng lặp có thể đang bị kẹt`);
  return null;
}

if (import.meta.url === pathToFileURL(process.argv[1] ?? "").href) {
  const q =
    process.argv[2] ??

}

    },
  },

    schema: {
      type: "object",

      required: ["expression"],
    },
  },
] as const;

// Dữ liệu GIẢ LẬP cho bài tập (không phải số liệu chính thức).
const MOCK_FACTS: [string, string][] = [
  ["hà nội", "Dân số Hà Nội năm 2024 khoảng 8,7 triệu người (số liệu giả lập)."],
  ["hồ chí minh", "Dân số TP. Hồ Chí Minh năm 2024 khoảng 9,5 triệu người (số liệu giả lập)."],
  ["hcm", "Dân số TP. Hồ Chí Minh năm 2024 khoảng 9,5 triệu người (số liệu giả lập)."],
];

export function webSearch(query: string): string {
  const q = query.toLowerCase();
  const hit = MOCK_FACTS.find(([k]) => q.includes(k));
  return hit ? hit[1] : `Không tìm thấy kết quả cho '${query}'.`;
}

export class CalcError extends Error {}

const TOKEN = /\d+(?:[.,]\d+)?|[-+*/()]/g;

// Parser đệ quy nhỏ cho + - * / ( ) — không dùng eval.
export function evaluate(str: string): number {
  const tokens = (str.match(TOKEN) ?? []).map((t) => t.replace(",", "."));
  const rest = str.replace(TOKEN, "").replace(/\s/g, "");
  if (rest) throw new CalcError(`ký tự không hợp lệ: ${rest}`);

  const expr = (): number => {
    let v = term();
    while (tokens[0] === "+" || tokens[0] === "-") v = tokens.shift() === "+" ? v + term() : v - term();
    return v;
  };
  const term = (): number => {
    let v = factor();
    while (tokens[0] === "*" || tokens[0] === "/") {
      if (tokens.shift() === "*") v *= factor();
      else {
        const d = factor();
        if (d === 0) throw new CalcError("chia cho 0");
        v /= d;
      }
    }
    return v;
  };
  const factor = (): number => {
    const t = tokens.shift();
    if (t === undefined) throw new CalcError("biểu thức chưa đầy đủ");
    if (t === "(") {
      const v = expr();
      if (tokens.shift() !== ")") throw new CalcError("thiếu ')'");
      return v;
    }
    if (t === "-") return -factor();
    if (t === "+") return factor();
    const n = Number(t);
    if (Number.isNaN(n)) throw new CalcError(`token không hợp lệ: ${t}`);
    return n;
  };

  const v = expr();
  if (tokens.length) throw new CalcError(`thừa token: ${tokens.join("")}`);
  return v;
}

/** Làm tròn 4 chữ số, in giống bản gốc (số nguyên vẫn có ".0"). */
export function formatNumber(v: number): string {
  const r = Math.round(v * 1e4) / 1e4;
  return Number.isInteger(r) ? `${r}.0` : String(r);
}

/** Chạy một tool theo tên. Trả [output, isError]; lỗi input trả về để Claude tự sửa. */
export function runTool(name: string, input: Record<string, unknown>): [string, boolean] {
  try {
    switch (name) {
      case "web_search":
        return [webSearch(String(input.query ?? "")), false];
      case "calculator":
        return [formatNumber(evaluate(String(input.expression ?? ""))), false];
      default:
        return [`Tool không tồn tại: ${name}`, true];
    }
  } catch (e) {
    if (e instanceof CalcError) return [`Lỗi: ${e.message}`, true];
    throw e;
  }
}

6. Tiêu chí hoàn thành

  • 2 tool có JSON Schema đúng chuẩn
  • Vòng lặp gọi Messages API và kiểm tra stop_reason
  • Chạy tool và nối tool_result vào hội thoại
  • Thoát vòng lặp khi end_turn và lấy được text cuối
  • Có ít nhất 2 lượt gọi tool liên tiếp trước khi xong (kịch bản test có 3)
  • MAX_ITERATIONS có cảnh báo, chỉ kích hoạt khi bất thường

7. Bài học rút ra

  • stop_reason là tín hiệu duy nhất đáng tin để dừng vòng lặp. Lượt 0 vừa có text vừa có tool_use: check theo loại content sẽ dừng sai ngay ở đây.
  • Quên nối tool_result thì lượt sau Claude không biết kết quả. Nhiều tool call trong một lượt thì gửi mọi kết quả trong một message user.
  • Lỗi tool nên trả về cho Claude (is_error + thông báo rõ), không nên nuốt lỗi. Claude đã tự sửa input ở lượt 2.
  • Giới hạn số vòng chỉ là lưới an toàn. Đừng dùng nó làm cách kết thúc chính, và đừng ép tool_choice: any để chống trả text, vì sẽ gây vòng lặp vô hạn.

== Đối chiếu với vòng lặp tự viết (bai_1_1_agentic_loop.ts)
- Bản API: code của mình gọi Messages API, đọc stop_reason, chạy tool, nối tool_result, quyết định dừng.
- Bản CLI: Claude Code làm toàn bộ việc đó. Mỗi "Lượt" ở trên tương ứng một vòng `for (i < MAX_ITERATIONS)`
  của bản API; mỗi dòng ↳ tương ứng một phần tử `results` trong message user.
- KHÔNG làm được bằng CLI: tự đặt điều kiện dừng, tự xử lý stop_reason lạ (max_tokens, refusal),
  tự quyết MAX_ITERATIONS. Ở đây chỉ QUAN SÁT được vòng lặp của Claude Code.
Chưa chạy với Claude thật. Chưa xác nhận: (1) stream-json thật có điền stop_reason ở mỗi lượt không (parser đã có đường suy ra); (2) --tools "" chỉ tắt tool built-in mà vẫn giữ tool MCP; (3) haiku có gọi 2 web_search trong cùng một lượt như kịch bản giả không. Chi phí ước tính: 1 lần chạy với haiku, 3–6 lượt API ≈ 0,03–0,10 USD, chặn trần 0,3 USD.
