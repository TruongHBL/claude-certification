Bài tập 1.4 — Prerequisite Gate cho thao tác tài chính

Domain 1 · Agentic Architecture & Orchestration · Mục 1.4 Workflow Enforcement & Handoff
Người thực hiện: TruongNQ · Ngày nộp: 08/10/2026

1. Mục tiêu

Xây agent chăm sóc khách hàng bằng Messages API (TypeScript) với 3 tool get_customer, lookup_order, process_refund và tool chuyển giao escalate_to_human. Hai điểm chính:

  • Cổng chặn bằng code: process_refund bị chặn cho đến khi get_customer trả về verified: true trong phiên. Prompt có dặn cũng không thay được cổng này.
  • Handoff có cấu trúc: khi phải chuyển cho người, bản tóm tắt bắt buộc đủ 5 trường và tự đủ nghĩa, vì nhân viên không đọc được hội thoại.

// ---------- Dữ liệu GIẢ LẬP ----------
const CUSTOMERS: Record<string, { customer_id: string; phone_last4: string; name: string }> = {
  "an@example.com": { customer_id: "C-001", phone_last4: "6789", name: "Nguyễn An" },
};
const ORDERS: Record<string, { customer_id: string; amount: number; status: string; item: string; payment: string }> = {
  "ORD-1001": { customer_id: "C-001", amount: 120.0, status: "delivered", item: "Tai nghe", payment: "visa-4242" },
  "ORD-1002": { customer_id: "C-001", amount: 45.0, status: "delivered", item: "Ốp lưng", payment: "visa-4242" },
  "ORD-2001": { customer_id: "C-002", amount: 300.0, status: "delivered", item: "Loa", payment: "mc-5555" },
};

// Trạng thái của MỘT phiên hội thoại — cổng chặn đọc từ đây.
export interface SessionState {
  verified_customer_id: string | null;
  ledger: { order_id: string; amount: number; reason: unknown }[]; // mọi refund ĐÃ thực thi
  handoffs: Record<string, unknown>[];
}

export const newState = (): SessionState => ({ verified_customer_id: null, ledger: [], handoffs: [] });

export class ToolError extends Error {
  blocked: boolean;
  constructor(message: string, blocked = false) {
    super(message);
    this.blocked = blocked;
  }
}

const PLACEHOLDER = /^\s*(tbd|todo|n\/?a|unknown|none|null|-+|\.{3}|…|\?+)?\s*$/i;
const isPlaceholder = (v: unknown) => PLACEHOLDER.test(String(v ?? ""));

type Args = Record<string, unknown>;

function getCustomer(state: SessionState, args: Args) {
  const c = CUSTOMERS[String(args.email ?? "").toLowerCase()];
  if (!c) return { verified: false, message: "Không tìm thấy khách với email này" };
  if (c.phone_last4 !== String(args.phone_last4 ?? ""))
    return { verified: false, customer_id: c.customer_id, message: "Sai 4 số cuối điện thoại" };

  state.verified_customer_id = c.customer_id; // CHỈ set khi tool thật sự trả verified: true
  return { verified: true, customer_id: c.customer_id, name: c.name };
}

function lookupOrder(_state: SessionState, args: Args) {
  const o = ORDERS[String(args.order_id)];
  if (!o) throw new ToolError(`Không có đơn ${args.order_id}`);
  return { ...o, order_id: args.order_id };
}

// ---- PREREQUISITE GATE ----
function processRefund(state: SessionState, args: Args) {
  const verified = state.verified_customer_id;
  const customerId = String(args.customer_id);
  const orderId = String(args.order_id);
  const amount = Number(args.amount);
  if (!verified)
    throw new ToolError(
      "BLOCKED: chưa xác minh khách hàng trong phiên này. " +
        "Hãy gọi get_customer và nhận verified=true trước khi hoàn tiền.",
      true,
    );
  if (customerId !== verified)
    throw new ToolError(`BLOCKED: customer_id ${customerId} khác khách đã xác minh (${verified}).`, true);
  const o = ORDERS[orderId];
  if (!o) throw new ToolError(`Không có đơn ${orderId}`);
  if (o.customer_id !== customerId) throw new ToolError(`BLOCKED: đơn ${orderId} không thuộc khách ${customerId}.`, true);
  if (amount > o.amount) throw new ToolError(`Số tiền ${amount} vượt giá trị đơn ${o.amount}.`);

  state.ledger.push({ order_id: orderId, amount, reason: args.reason }); // side effect thật
  return { status: "refunded", refund_id: `RF-${state.ledger.length}`, order_id: orderId, amount };
}

// ---- STRUCTURED HANDOFF ----
function escalateToHuman(state: SessionState, args: Args) {
  const keys = ["customer_id", "conversation_summary", "root_cause_analysis", "recommended_action"] as const;
  const fields = Object.fromEntries(keys.map((k) => [k, args[k]]));
  const bad: string[] = keys.filter((k) => isPlaceholder(args[k]));
  const refundAmount = args.refund_amount;
  if (!(typeof refundAmount === "number" && refundAmount >= 0)) bad.push("refund_amount");
  const concerns = Array.isArray(args.concerns) ? (args.concerns as unknown[]) : [];
  if (concerns.length === 0 || concerns.some((c) => (c && typeof c === "object" ? isPlaceholder((c as Args).detail) : true)))
    bad.push("concerns");
  if (bad.length) throw new ToolError(`Handoff bị từ chối – trường rỗng/placeholder: ${bad.join(", ")}. Hãy điền cụ thể.`);

  const ticket = {
    ticket_id: `HO-${String(state.handoffs.length + 1).padStart(4, "0")}`,
    ...fields,
    refund_amount: refundAmount,
    concerns,
  };
  state.handoffs.push(ticket);
  return { status: "escalated", ticket_id: ticket.ticket_id };
}

const HANDLERS: Record<string, (state: SessionState, args: Args) => object> = {
  get_customer: getCustomer,
  lookup_order: lookupOrder,
  process_refund: processRefund,
  escalate_to_human: escalateToHuman,
};

export const isTool = (name: string) => name in HANDLERS;

/** Gọi handler: thiếu tham số bắt buộc hoặc tool lạ → ToolError (lỗi có cấu trúc, Claude đọc được).
 *  escalate_to_human tự kiểm đủ trường bằng validator (để báo đủ danh sách trường còn thiếu). */
export function callTool(state: SessionState, name: string, args: Args): object {
  const handler = HANDLERS[name];
  if (!handler) throw new ToolError(`Tool không tồn tại: ${name}`);
  const required =
    name === "escalate_to_human" ? [] : ((TOOLS.find((t) => t.name === name)!.input_schema.required as string[]) ?? []);
  const missing = required.filter((k) => args[k] === undefined || args[k] === null);
  if (missing.length) throw new ToolError(`Thiếu tham số bắt buộc: ${missing.join(", ")}`);
  return handler(state, args);
}

// Bài 1.4 – Build Exercise: Prerequisite Gate for Financial Operations (bản Messages API).
//
// Agent CSKH có 4 tool: get_customer, lookup_order, process_refund, escalate_to_human (xem support_tools.ts).
// - Cổng chặn (prerequisite gate) nằm trong CODE của handler process_refund, không nằm trong prompt:
//   chưa có get_customer trả về verified: true trong phiên này → trả lỗi BLOCKED, không thực thi.
// - escalate_to_human bắt buộc đủ 5 trường; validator trong code từ chối trường rỗng/placeholder.
//
// Chạy:  export ANTHROPIC_API_KEY=...
//        node --experimental-strip-types bai_1_4_prerequisite_gate.ts skip    # prompt ép bỏ qua xác minh
//        node --experimental-strip-types bai_1_4_prerequisite_gate.ts multi   # yêu cầu gồm 3 vấn đề → handoff
// Không có API key: dùng bản CLI (./run_cli.sh).
import { readFileSync } from "node:fs";
import { fileURLToPath } from "node:url";
import { httpTransport, textOf, toolUsesOf, type Message, type Transport, type UserBlock } from "../lib/anthropic.ts";
import { SYSTEM, TOOLS, ToolError, callTool, newState, type SessionState } from "./support_tools.ts";

const MODEL = process.env.ANTHROPIC_MODEL ?? "claude-sonnet-5-5";
const MAX_ITERATIONS = 20; // lưới an toàn

/** Chạy một tool → [nội dung tool_result, is_error]. Lỗi có cấu trúc → Claude đọc được và tự xử lý. */
export function runTool(state: SessionState, name: string, input: Record<string, unknown>): [string, boolean] {
  try {
    const out = callTool(state, name, input);
    if (name === "escalate_to_human")
      console.log(`\n=== HANDOFF gửi nhân viên ===\n${JSON.stringify(state.handoffs.at(-1), null, 2)}\n`);
    return [JSON.stringify(out), false];
  } catch (e) {
    if (e instanceof ToolError) return [e.message, true];
    throw e;
  }
}

// ---------- Agentic loop (như bài 1.1) ----------
export async function agent(
  userMessage: string,
  state: SessionState = newState(),
  transport: Transport = httpTransport(),
): Promise<string | null> {
  const messages: Message[] = [{ role: "user", content: userMessage }];
  for (let i = 0; i < MAX_ITERATIONS; i++) {
    const r = await transport({ model: MODEL, max_tokens: 2000, system: SYSTEM, tools: TOOLS, messages });
    messages.push({ role: "assistant", content: r.content });

    if (r.stop_reason === "end_turn") return textOf(r);
    if (r.stop_reason !== "tool_use") throw new Error(`Dừng bất thường: stop_reason=${r.stop_reason}`);

    const results: UserBlock[] = toolUsesOf(r).map((b) => {
      const [out, err] = runTool(state, b.name, b.input);
      console.log(`[iter ${i}] ${b.name}${err ? " ✗" : ""} → ${out}`);
      return { type: "tool_result", tool_use_id: b.id, content: out, is_error: err };
    });
    messages.push({ role: "user", content: results });
  }
  console.warn(`CẢNH BÁO: chạm MAX_ITERATIONS=${MAX_ITERATIONS}`);
  return null;
}

/** Kịch bản dùng chung với bản CLI (scenarios.json): normal, skip, wrongphone, multi. */
export function scenarioText(id: string): string {
  const { scenarios } = JSON.parse(readFileSync(new URL("./scenarios.json", import.meta.url), "utf8")) as {
    scenarios: { id: string; text: string }[];
  };
  const s = scenarios.find((x) => x.id === id);
  if (!s) throw new Error(`Không có kịch bản ${id} (có: ${scenarios.map((x) => x.id).join(", ")})`);
  return s.text;
}

if (process.argv[1] === fileURLToPath(import.meta.url)) {
  const state = newState();
  console.log(await agent(scenarioText(process.argv[2] ?? "skip"), state));
  console.log(`\nLedger (refund đã thực thi): ${JSON.stringify(state.ledger)}`);
}

6. Tiêu chí hoàn thành

  • 3 tool có input_schema JSON Schema đúng chuẩn
  • State theo phiên ghi nhận khách đã xác minh, handler process_refund kiểm tra trước khi chạy
  • Gọi refund khi chưa xác minh → bị chặn; sau get_customer → refund thành công
  • Handoff có đủ 5 trường, không rỗng, không placeholder
  • Yêu cầu nhiều vấn đề: cả 3 vấn đề có mặt trong handoff với chi tiết cụ thể

7. Bài học rút ra

  • Prompt là xác suất, cổng chặn là tất định. Hướng dẫn trong prompt đúng khoảng 92% lần; cổng trong code đúng 100% vì tool không thể chạy khi thiếu điều kiện. Tiền, bảo mật, tuân thủ thì phải dùng cổng chặn bằng code.
  • State phải lấy từ kết quả tool, không lấy từ lời Claude. Khách nói “tôi là C-001” không làm SessionState thay đổi. Chỉ get_customer trả verified: true mới mở cổng.
  • Bị chặn thì trả lỗi rõ ràng cho Claude (cần làm gì để mở cổng), để agent tự sửa thứ tự gọi tool thay vì dừng hẳn.
  • Handoff phải tự đủ nghĩa. Người nhận không có transcript, nên thiếu customer ID hoặc recommended action là handoff hỏng. Validator trong code đảm bảo điều này, không để Claude tự giác.
  • Bẫy đề thi hay gặp: “thêm hướng dẫn vào system prompt”, “thêm few-shot”, “thêm routing classifier” để sửa lỗi tuân thủ tài chính, đều là đáp án sai. Đáp án đúng là chặn bằng code (prerequisite gate / hook).

Cổng chặn đặt ở đâu: trong server, không dùng hook

Cách chính: cổng chặn nằm trong code handler process_refund của MCP server, giống bản API. Lý do:

  • Điều kiện "đã xác minh" là kết quả của get_customer (verified: true), và chỉ server biết kết quả đó. Hook PreToolUse chỉ thấy input của lệnh sắp chạy, muốn biết đã xác minh chưa phải tự đọc lại transcript hoặc file state, thêm một chỗ có thể lệch.
  • Server chạy được và test được không cần model (bơm JSON-RPC), nên cổng chặn kiểm chứng tất định.
  • Mỗi lệnh claude -p khởi chạy server mới, nên state phiên ghi ra STATE_FILE; một file state = một phiên.

Hook PreToolUse (--settings, matcher mcp__support__process_refund, exit 2) có thể thêm làm lớp phòng thủ thứ hai, nhưng bài này không cần.

Tool lạ (không có trong 4 tool) giờ trả lỗi giao thức JSON-RPC -32602 thay vì isError: tool không chạy, đúng lớp lỗi theo bài 2.2. Server vẫn ghi log lần gọi đó.
