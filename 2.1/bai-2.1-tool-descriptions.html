1. Mục tiêu

Model chọn tool chủ yếu dựa vào name + description. Bài này tái hiện lỗi misrouting khi hai tool có mô tả mơ hồ, chồng lấn; sửa bằng mô tả đủ 5 yếu tố (mục đích, input, ví dụ, giới hạn, ranh giới); rồi tìm câu nhạy từ khoá trong system prompt có thể đè lên mô tả tốt. Ba cấu hình A/B/C tách riêng tác động của mô tả và của system prompt, chấm tự động theo nhãn.

def log_call(name, args)
  return unless LOG_FILE

  File.open(LOG_FILE, "a") do |f|
    f.puts JSON.generate({ at: Time.now.iso8601, toolset: TOOLSET, tool: name, arguments: args })
  end
end

# Ở bản vague, field `query` là chuỗi tự do: dò mọi kiểu định danh trong chuỗi.
def find_customer(args)
  q = [args["customer_id"], args["email"], args["phone"], args["query"]].compact.join(" ")
  CUSTOMERS.find do |c|
    q.include?(c[:customer_id]) || q.downcase.include?(c[:email]) || q.gsub(/\D/, "").include?(c[:phone])
  end
end

def find_order(args)
  q = [args["order_number"], args["tracking_id"], args["query"]].compact.join(" ")
  ORDERS.find { |o| q.include?(o[:order_number]) || (o[:tracking_id] && q.include?(o[:tracking_id])) }
end

def call_tool(name, args)
  log_call(name, args)
  result =
    case name
    when "get_customer" then find_customer(args)
    when "lookup_order" then find_order(args)
    else return { content: [{ type: "text", text: JSON.generate({ error: "unknown_tool", tool: name }) }], isError: true }
    end
  if result
    { content: [{ type: "text", text: JSON.generate(result) }] }
  else
    { content: [{ type: "text", text: JSON.generate({ error: "not_found", input: args }) }], isError: true }
  end
end

def respond(id, result) = $stdout.puts(JSON.generate({ jsonrpc: "2.0", id: id, result: result }))

def respond_error(id, code, message)
  $stdout.puts(JSON.generate({ jsonrpc: "2.0", id: id, error: { code: code, message: message } }))
end

$stdout.sync = true
$stdin.each_line do |line|
  next if line.strip.empty?

  begin
    msg = JSON.parse(line)
  rescue JSON::ParserError
    respond_error(nil, -32_700, "Parse error")
    next
  end
  id = msg["id"]
  case msg["method"]
  when "initialize"
    respond(id, { protocolVersion: msg.dig("params", "protocolVersion") || "2025-06-18",
                  capabilities: { tools: {} },
                  serverInfo: { name: "shop", version: "1.0.0" } })
  when "notifications/initialized", "notifications/cancelled"
    nil # notification: không trả lời
  when "ping"
    respond(id, {})
  when "tools/list"
    respond(id, { tools: TOOLS })
  when "tools/call"
    respond(id, call_tool(msg.dig("params", "name"), msg.dig("params", "arguments") || {}))
  else
    respond_error(id, -32_601, "Method not found: #{msg['method']}") unless id.nil?
  end
end

#!/usr/bin/env bash
# Bài 2.1 – chạy 10 query qua Claude Code CLI với 3 cấu hình rồi chấm tool được gọi ĐẦU TIÊN.
#
#   A = mô tả vague + system prompt conflict   (tình trạng ban đầu)
#   B = mô tả clear + system prompt conflict   (chỉ sửa mô tả)
#   C = mô tả clear + system prompt fixed      (sửa cả mô tả lẫn system prompt)
#
# Dùng:  ./run.sh A | B | C | all     chạy (MỖI query một lệnh `claude -p` riêng, không chung context)
#        ./run.sh score               in bảng độ chính xác + danh sách câu sai
#        ./run.sh clean               xoá results/
#
# Chi phí ước tính (haiku): ~10–20k token input mỗi lệnh (system prompt CLI + mô tả tool), 1–2 lượt.
# 30 lệnh ≈ 0,3–0,8 USD. Mỗi lệnh bị chặn trần bằng --max-budget-usd.
set -euo pipefail

ROOT="$(cd "$(dirname "${BASH_SOURCE[0]}")" && pwd)"
RESULTS="$ROOT/results"
MODEL="${MODEL:-haiku}"
BUDGET="${BUDGET:-0.2}"
CLAUDE_BIN="${CLAUDE_BIN:-claude}"

toolset_of() { case "$1" in A) echo vague ;; B|C) echo clear ;; esac; }
prompt_of()  { case "$1" in A|B) echo "$ROOT/prompts/system_conflict.txt" ;; C) echo "$ROOT/prompts/system_fixed.txt" ;; esac; }

run_config() {
  local cfg="$1" toolset prompt dir n
  toolset="$(toolset_of "$cfg")"; prompt="$(prompt_of "$cfg")"
  dir="$RESULTS/$cfg"; mkdir -p "$dir"
  n="$(ruby -rjson -e 'puts JSON.parse(File.read(ARGV[0]))["queries"].size' "$ROOT/queries.json")"
  echo "== Cấu hình $cfg: TOOLSET=$toolset, prompt=$(basename "$prompt"), model=$MODEL"
  for ((i = 0; i < n; i++)); do
    local id text mcp
    id="$(ruby -rjson -e 'puts JSON.parse(File.read(ARGV[0]))["queries"][ARGV[1].to_i]["id"]' "$ROOT/queries.json" "$i")"
    text="$(ruby -rjson -e 'puts JSON.parse(File.read(ARGV[0]))["queries"][ARGV[1].to_i]["text"]' "$ROOT/queries.json" "$i")"
    mcp="$dir/q$id.mcp.json"
    rm -f "$dir/q$id.log"
    # Mỗi query một file cấu hình MCP để log tool call tách riêng theo query.
    ruby -rjson -e 'puts JSON.pretty_generate({ mcpServers: { shop: { type: "stdio", command: "ruby", args: [ARGV[0]],
                      env: { TOOLSET: ARGV[1], SHOP_LOG: ARGV[2] } } } })' \
      "$ROOT/shop_mcp_server.rb" "$toolset" "$dir/q$id.log" > "$mcp"
    echo "  q$id: $text"
    # Chạy trong thư mục rỗng để không nạp CLAUDE.md/settings của project nào.
    (cd "$RESULTS" && "$CLAUDE_BIN" -p "$text" \
      --model "$MODEL" \
      --system-prompt "$(cat "$prompt")" \
      --mcp-config "$mcp" --strict-mcp-config \
      --tools "" \
      --allowedTools "mcp__shop__get_customer" "mcp__shop__lookup_order" \
      --permission-mode dontAsk \
      --max-budget-usd "$BUDGET" \
      --no-session-persistence \
      --output-format stream-json --verbose \
      > "$dir/q$id.jsonl" 2> "$dir/q$id.err") || echo "    (lệnh trả mã lỗi, xem $dir/q$id.err)"
  done
}

case "${1:-}" in
  A|B|C) run_config "$1" ;;
  all)   for c in A B C; do run_config "$c"; done; ruby "$ROOT/score.rb" "$RESULTS" "$ROOT/queries.json" ;;
  score) ruby "$ROOT/score.rb" "$RESULTS" "$ROOT/queries.json" ;;
  clean) rm -rf "$RESULTS" ;;
  *) echo "Dùng: $0 A|B|C|all|score|clean"; exit 1 ;;
esac

File score.rb

# frozen_string_literal: true

# Bài 2.1 – chấm tool được gọi ĐẦU TIÊN cho từng query, từng cấu hình.
# Nguồn chính: block tool_use đầu tiên trong stream-json (qN.jsonl).
# Dự phòng: dòng đầu của log server (qN.log), nếu stream-json không đọc được.
# Dùng: ruby score.rb results queries.json

require "json"

results_dir, queries_file = ARGV
queries = JSON.parse(File.read(queries_file))["queries"]
CONFIGS = { "A" => "vague + conflict", "B" => "clear + conflict", "C" => "clear + fixed" }.freeze

def first_tool_from_stream(path)
  return nil unless File.exist?(path)

  File.foreach(path) do |line|
    ev = JSON.parse(line) rescue next
    next unless ev["type"] == "assistant"

    Array(ev.dig("message", "content")).each do |b|
      return b["name"].sub(/\Amcp__shop__/, "") if b["type"] == "tool_use"
    end
  end
  nil
end

def first_tool_from_log(path)
  return nil unless File.exist?(path) && !File.zero?(path)

  JSON.parse(File.foreach(path).first)["tool"]
end

summary = []
CONFIGS.each do |cfg, label|
  dir = File.join(results_dir, cfg)
  next unless Dir.exist?(dir)

  rows = queries.map do |q|
    got = first_tool_from_stream(File.join(dir, "q#{q['id']}.jsonl")) ||
          first_tool_from_log(File.join(dir, "q#{q['id']}.log")) || "(không gọi tool)"
    { id: q["id"], text: q["text"], expected: q["expected"], got: got, ok: got == q["expected"] }
  end
  correct = rows.count { _1[:ok] }
  summary << [cfg, label, correct, rows.size]
  puts "\n== #{cfg} (#{label}): #{correct}/#{rows.size}"
  rows.reject { _1[:ok] }.each do |r|
    puts "   ✗ q#{r[:id]}: cần #{r[:expected]}, gọi #{r[:got]}  | #{r[:text]}"
  end
end

if summary.empty?
  puts "Chưa có kết quả trong #{results_dir}. Chạy ./run.sh all trước."
  exit 1
end
puts "\nCấu hình             Đúng"
summary.each { |cfg, label, c, n| puts format("%-2s %-17s %2d/%d", cfg, label, c, n) }
File.write(File.join(results_dir, "score.json"),
           JSON.pretty_generate(summary.map { |cfg, label, c, n| { config: cfg, label: label, correct: c, total: n } }))

  • Sửa system prompt mới đạt 10/10 ở cả hai lượt (C). Kết quả này khớp bước 5 của đề: câu nhạy từ khoá trong system prompt đè lên mô tả tốt.

10. Tiêu chí hoàn thành

  • Có so sánh độ chính xác trước/sau trên cùng 10 query (A → B → C, chấm tự động bằng score.rb)
  • Mô tả mới nêu định dạng định danh (#NNNNN, CUS-NNNN, mã vận đơn, SĐT 10 số) và ranh giới “KHÔNG dùng cho…” giữa hai tool
  • Có danh sách câu system prompt gây xung đột kèm bản viết lại (mục 5)
  • Mục tiêu khi chạy thật: C đạt 9–10/10. Đạt: 10/10 ở cả 2 lượt

11. Bài học rút ra

  • Description là cơ chế chọn tool chính. Mô tả một câu chồng lấn thì model đoán theo từ khoá. Sửa mô tả là bước đầu tiên: rẻ và nhắm thẳng nguyên nhân.
  • Mô tả tốt có 5 yếu tố: mục đích, định dạng input, ví dụ query, edge case/giới hạn, ranh giới với tool tương tự. Schema tách field có pattern giúp thêm, nhưng không thay được ranh giới viết bằng lời.
  • Bẫy đề thi (đều sai khi hỏi “bước đầu tiên”): thêm few-shot vào system prompt (tốn token, không sửa gốc), routing classifier theo từ khoá (quá nặng, bỏ qua khả năng hiểu ngôn ngữ của model), gộp tool thành một (hợp lệ về lâu dài nhưng tốn công hơn).
  • Sửa mô tả rồi phải đọc lại system prompt. Câu kiểu “luôn kiểm tra thông tin khách hàng” tạo liên kết từ khoá với một tool và đè lên mô tả tốt (cấu hình B vs C).
  • Tách tool khi tool quá chung (vd analyze_document → extract_data_points, summarize_content, verify_claim_against_source); đổi tên khi tên dễ nhầm (vd analyze_content → extract_web_results).
  • Giới hạn: mô tả chỉ chữa nhầm giữa một số ít tool. Khi một agent có quá ~4–5 tool, chọn sai vì số lượng; cách sửa là phân bổ tool theo vai trò (bài 2.3).
